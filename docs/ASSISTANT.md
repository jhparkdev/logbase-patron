# 로컬 AI 도우미 테스트

브랜치: `codex/agent-ollama-poc`

모든 업무 화면 우측 하단의 AI 버튼에서 채팅창을 연다. 기존 관리자 계정으로 로그인한 후 고객 실제 사용량·비용·예산(P01), 내부 프로젝트 비용·구독료·예산(P02), 등록 모델·서버 업체, 시뮬레이션 이력·결과를 조회하거나 P04 설정을 준비할 수 있다.

## 로컬 실행

1. [Ollama](https://ollama.com/download/windows)를 설치하고 실행한다.
2. PowerShell에서 모델을 내려받는다.

```powershell
ollama pull qwen3.5:4b
```

Ollama는 기본적으로 `http://127.0.0.1:11434`에서 실행된다. `ollama list`로 모델을 확인한다. 모델 이름에 `:cloud`가 붙은 원격 모델은 이 테스트에서 사용하지 않는다.

3. 백엔드를 실행할 PowerShell에서 다음 환경변수를 설정한다. DB와 기존 계정 등 프로젝트의 기본 개발 환경은 먼저 준비되어 있어야 한다.

```powershell
$env:ASSISTANT_ENABLED = "true"
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "qwen3.5:4b"
$env:OLLAMA_CONTEXT_LENGTH = "8192"
$env:ALLOWED_ORIGIN = "http://localhost:5173"
$env:SESSION_COOKIE_SECURE = "false"
uv --directory backend run fastapi dev app/main.py
```

`SESSION_COOKIE_SECURE=false`는 로컬 HTTP 테스트에만 사용한다. 개발 서버가 다른 포트를 사용하면 `ALLOWED_ORIGIN`을 실제 화면 주소에 맞춘다. 설정을 바꾸면 백엔드를 재시작한다.

4. 별도 PowerShell에서 프론트엔드를 실행한다.

```powershell
pnpm --dir frontend dev
```

5. 공통 로그인 화면에서 기존 관리자 계정으로 로그인한 뒤 업무 화면 우측 하단 AI 버튼을 누른다. 도우미는 전역 로그인 사용자 정보를 재사용하며 별도 로그인 폼이나 세션 조회 캐시를 두지 않는다. 도우미 API가 세션 만료·계정 비활성화 등으로 401을 반환하면 공통 로그인 화면으로 이동하고 대화와 진행 중인 도우미 요청을 정리한다. 백엔드는 각 도우미 API 요청에서 기존 세션을 검증한다. 기존 다른 기능 API의 인증 정책은 이번 변경 범위에 포함하지 않았다.

## 시험 요청

화면에서 순서대로 확인할 때는 [화면 검증 체크리스트](ASSISTANT-UI-CHECKLIST.md)를 사용한다.

- “현재 선택할 수 있는 모델을 알려줘.”
- “최근 시뮬레이션 이력을 보여줘.”
- “이 실행 ID의 결과를 요약해줘: …”
- P-04에서 “최대 출력 토큰만 2,048로 바꿔줘.”
- “Prompt를 다음 내용으로 바꿔줘: 핵심 내용 세 줄로 요약해 주세요.”
- “JSON 출력 형식에 title과 summary 문자열이 있도록 설정해줘.”
- P01에서 고객과 기간을 조회한 뒤 “현재 선택한 고객의 비용과 미확인 호출 건수를 정리해줘.”
- “가상고객A의 가장 최근 실제 API 호출 시각을 알려줘.”
- P02에서 “예산을 초과한 내부 프로젝트만 보여줘.”
- “프로젝트 이름의 10월 관리 비용과 구독료를 알려줘.” (실제 이름으로 바꾼다.)

## 화면 문맥과 사용량 조회

입력창 위의 ‘조회 기준’에 현재 화면과 적용된 기간·선택 대상이 표시된다. 조회 버튼으로 적용한 고객·프로젝트·서비스·모델 조건을 기본으로 사용한다. 아직 조회하지 않은 폼 입력은 전달하지 않는다. 고객·프로젝트 상세창이 열려 있으면 그 대상과 상세창의 월 전체 기간을 기준으로 한다. 화면 이동 후 새 질문은 이동한 화면의 조건을 사용하며 대화는 유지된다.

사용자가 이름이나 기간을 명시하면 화면보다 우선한다. 정확한 이름 또는 하나로 식별되는 일부 이름을 사용할 수 있고, 모호하거나 없는 이름은 확인을 요청한다. ‘전체 고객’, ‘전체 프로젝트’처럼 말하면 해당 대상 조건을 해제한다. 이전 질문의 고객·서비스·모델 이름은 그 질문이 사용량·비용·예산을 물은 경우에만 이어서 쓰며, 모델 가격·목록 질문에 나온 이름은 필터로 쓰지 않는다. P01의 고객 조건은 내부 비용 조회에 섞이지 않는다. 범위가 불명확하거나 고객·내부·시뮬레이션을 한 번에 섞어 요청하면 먼저 범위를 확인한다.

기간은 서버의 한국시간 날짜로 결정한다. ‘오늘’, ‘이번 달’(1일~오늘), ‘지난달’(월 전체), ‘최근 N일’(최대 366일), ‘어제’, ‘2026년 10월’, ‘10월’(올해), ‘10월 12일부터 15일까지’, ISO 날짜와 `2026/10/12`·`2026.10.12`·`10/12` 형식의 날짜·날짜 범위를 지원한다. ‘지난주’, ‘올해’, ‘최근 3개월’, ‘3분기’처럼 지원하지 않는 기간 표현은 화면 기간으로 바꾸지 않고 기간을 다시 지정하도록 안내한다. 기간을 말하지 않으면 해당 P01/P02 화면의 적용 기간을 유지한다. 다른 화면에서 조회할 때는 고객 최근 30일, 내부 이번 달을 기본으로 한다. 모델이 임의로 생성한 기간으로 기본 조건을 바꾸지 않는다. ‘가장 최근 호출’도 이 조회 기간 안의 최신 호출이다.

비용과 예산은 기존 화면의 집계 서비스를 사용한다. 확정·추정 금액과 금액 미확인 건수를 구분하며 미확인 금액은 합계에 포함하지 않는다. 구독료는 조회 기간에 걸친 각 달의 전체 청구액이다. 모델 필터를 적용한 내부 비용에는 구독료가 제외된다. 예산은 종료일이 속한 월 전체 기준이며, 고객 예산은 서비스·모델 필터와 관계없이 고객 전체 사용액을 사용한다.

합계·호출 내역·일별 추이·예산 상태를 조회할 수 있다. 목록은 도구 한 페이지당 5개이며 ‘다음 페이지’로 이어서 조회한다. 고객 예산 목록은 고객×서비스 행이므로 같은 고객 예산이 반복될 수 있다. ‘예산 초과’ 조건은 페이지를 나누기 전에 필터링한다. 출처 링크는 실제 조회한 대상·기간·정렬·예산 상태로 P01/P02를 연다. 화면 목록은 10개씩 표시하므로 도구 결과가 포함된 화면 페이지로 연결한다. 예산 상태 조건은 화면의 ‘예산 상태 조건 해제’ 버튼으로 지운다. 한 질문에서 여러 번 조회하면 서버가 작성한 합계·호출 내역 답변을 모두 표시하고, 예산·추이처럼 서버 문구가 없는 결과가 섞이면 그 뒤에 모델 설명을 덧붙인다.

P-04에서는 검증된 변경 필드만 바로 반영한다. 설정 도구는 바꾸거나 설정해 달라는 질문에서만 제공한다. 결과·이력·모델 조회 질문에서는 도구 결과의 응답 원문 등에 담긴 지시로 설정이 바뀌지 않는다. 다른 화면에서 준비한 설정은 시뮬레이터를 연 후 ‘설정 적용’을 누른다. 모델·Provider·추론 강도 등의 지원 여부를 검증하며, 지원하지 않거나 확인할 수 없는 조건은 성공으로 처리하지 않는다.

변경 후 ‘설정 되돌리기’를 사용할 수 있다. 요청 도중 입력을 편집하거나 다른 폼으로 이동하면 늦게 온 응답이 현재 폼을 덮어쓰지 않는다. 추가 편집이나 화면 이동 후에는 이전 변경을 되돌릴 수 없을 수 있다.

일반 답변의 시간대가 있는 ISO 날짜는 한국시간으로 표시하고 소수 초를 생략한다. 문단·굵은 강조·목록·코드 블록을 구분하며, HTML이나 모델이 만든 링크는 실행하지 않는다. 건수·토큰 수와 USD 금액은 기존 화면의 표시 규칙을 따른다. 원문·ISO·JSON·UTC·정밀 시각 요청은 원시 값을 유지하며 코드 블록도 변환하지 않는다. 표시용 변환은 다음 요청의 대화 원문이나 실제 설정값을 바꾸지 않는다. 응답 작성 지침을 바꾼 뒤에는 백엔드를 재시작하고 새 대화로 확인한다.

실행별 출처인 ‘실행 상세 · 요청 시각’을 누르면 P05로 이동하면서 기존 ‘시뮬레이션 실행 상세’ 창을 연다. 출처는 실제 조회한 실행 ID로만 만들며, 해당 실행의 요청일·ID로 목록도 조회한다. 여러 실행이면 요청 시각으로 구분한다. 실행 ID가 없는 일반 ‘시뮬레이션 이력’ 링크는 목록만 연다. 이전 응답에는 실행 ID가 없을 수 있으므로 연결 변경은 새 질문으로 확인한다.

## 모델 개수·목록·실행 업체

- “지금 사용 가능한 모델의 개수를 알려줘”에는 등록 모델 중 ‘사용 중’ 상태의 전체 개수만 답한다. 개수 조회는 모델 행·가격·실행 업체를 가져오지 않는다.
- 일반 모델 목록에는 모델명과 DB의 모델 제공사만 표시한다. 전체 개수와 현재 페이지의 순번 범위(예: 10개 중 1~5번째)를 구분한다. 빈 결과와 범위를 벗어난 페이지도 구분한다.
- 실행 업체는 업체를 명시적으로 질문하거나 모델 선택·설정 준비에 필요할 때만 조회한다. 모델 제공사와 실행 업체를 별도 항목으로 표시하며, 업체 목록이 실제 호출 성공을 검증한 결과는 아니라고 안내한다.
- 조회 기준은 전체 등록 모델의 ‘사용 중’ 상태다. 모델명·ID 검색어가 있으면 검색 기준을 답변에 함께 표시한다. 화면의 제공사·상태 필터를 자동으로 적용한 결과로 표현하지 않는다.

## 실행 결과 정량 비교

- P04의 실행 결과 또는 P05의 실행 상세를 연 뒤 “선택한 실행의 모델별 결과를 비교해줘”, “어떤 모델이 더 빠르고 저렴했어?”라고 요청한다. 다른 화면에서는 “실행 결과 비교: 실행 UUID”처럼 ID 한 개를 지정한다.
- 한 실행 안의 전체 항목을 비교한다. 대상이 없거나 최근·다른 실행을 요청하면 실행 선택 또는 ID 확인을 요청한다. 서로 다른 실행 간 비교는 제공하지 않는다.
- 비용과 비용 상태, 응답시간(ms), 입력·출력 토큰, JSON·Schema 검증 상태를 저장된 결과에서 표시한다. 미확인·미적용·미실행은 구분하고, 요청 업체와 실제 처리 업체가 다르면 함께 표시한다.
- 종료된 실행에서 성공 항목이 2개 이상일 때만 성공 항목 간 최저 비용·최단 응답시간과 최고·최저 차이를 계산한다. 비용은 성공 항목 모두 확정일 때, 시간은 성공 항목 모두 확인될 때만 순위를 표시한다. 동률과 0을 그대로 처리한다.
- 진행 중이거나 일부 항목이 없는 실행은 순위를 판단하지 않는다. 실패·취소 항목의 수치는 표시하되 순위에서 제외한다. 실행 설정이 다르면 동일 조건 비교가 아니라는 안내를 표시한다.
- 비교 요청은 기존 상세 조회 도구를 사용하고, 서버가 수치·문구를 직접 작성한다. Ollama 생성 응답, 응답 원문, 임의 오류 문구는 비교 판단에 사용하지 않는다. 결과에는 실제 실행 상세 출처가 연결된다.
- 이번 실행의 관측값이며 일반적인 모델 성능 순위나 응답 품질·정답 여부를 평가하지 않는다. 새 비교 실행이나 유료 추론을 시작하지 않는다.

## 범위와 비용

- 대화는 브라우저 메모리에만 보관한다. 채팅창을 닫거나 앱 내부 화면을 이동해도 유지하며, 새로고침·탭 종료·로그아웃·계정 변경·대화 지우기로 초기화한다.
- 서버는 필요한 대화 문맥을 요청 단위로 처리하고 대화 DB 행이나 프롬프트·응답 로그를 생성하지 않는다. 전송하는 문맥은 최근 최대 12개 메시지·8,000자로 제한한다. 화면에는 최대 40개 메시지를 유지한다.
- 도구는 고객 사용량 조회, 내부 비용 조회, 등록 모델 조회, 이력 조회, 결과 조회, 설정 초안 준비의 여섯 종류다. 임의 SQL, 임의 함수 실행, 모델 등록·삭제, 예산·구독료 변경, 비교 자동 실행은 제공하지 않는다.
- 신규 모델 알림과 자동 비교는 후속 범위다.
- 설정 도구는 시뮬레이션·AI 호출 이력을 만들지 않는다. 기존 ‘비교 실행’ 버튼을 사용하면 OpenRouter 추론 비용이 발생할 수 있다.
- 서버 업체 목록은 기존 공개 OpenRouter 조회를 사용하므로 인터넷 연결이 필요하다. 이는 OpenRouter의 유료 모델 추론 호출과 별개다.
- 에이전트는 기본 비활성화다. 활성화 여부와 모델 주소·이름은 서버 설정으로만 관리한다. 새 의존성·DB 마이그레이션·배포 설정은 추가하지 않았다.
- 로컬 GPU 보호를 위해 한 번에 한 요청을 처리하며, 요청당 최대 4회 모델 왕복·8회 도구 호출·120초로 제한한다. 통신 실패는 자동 재시도하지 않는다. 사용량 답변에서 조회를 생략하면 이 왕복 한도 안에서 한 번만 도구 호출을 재안내하고, 그래도 조회 결과가 없으면 답변을 차단한다.

## 확인할 사항

8GB VRAM에서는 4B 양자화 모델과 8K 문맥부터 시험한다. `ollama ps`로 GPU 적재 상태를 확인하고, 메모리 여유가 부족하면 문맥을 4096으로 줄이고 대화를 지운 뒤 짧은 요청으로 시험한다. 긴 대화·도구 결과는 작은 문맥에서 정확도가 떨어질 수 있다.

자동 테스트는 가짜 Ollama·가짜 Provider 조회와 실제 `patron_test` DB를 사용한다. 별도로 실제 Qwen으로 기존 기본 시나리오 10개와 사용량·문맥 시나리오 9개를 확인했다. 환경과 측정값, 검증 범위는 [실제 모델 검증 기록](ASSISTANT-LIVE-TEST.md)에 정리했다. 작은 모델의 자유 형식 설명에는 누락이나 표현 오류가 있을 수 있으므로 출처 화면의 같은 조건과 대조한다. 실제 조회 없이 생성한 사용량·비용 답변은 서버에서 차단한다.
