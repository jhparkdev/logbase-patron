검증일: 2026-11-03. 대상 브랜치: `codex/agent-ollama-poc`.

| 항목 | 확인값 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 4060 Laptop GPU, VRAM 8,188 MiB |
| 설치한 Windows Ollama 클라이언트 | 0.40.13 |

| GPU 메모리 관측 | 추론 중 전체 사용량 3,963 MiB / 8,188 MiB |

Windows Ollama를 설치하고 모델을 내려받았다. 다운로드와 검증은 기존 11434 포트의 WSL 서버를 통해 진행했으므로 모델은 해당 서버의 캐시에 있다. 기존 서버를 종료하거나 업그레이드하지 않았다. 이후 Windows 서버로 전환하면 별도 모델 다운로드가 필요할 수 있다.

## 검증 방식

실제 Qwen 모델 → 네이티브 Ollama 도구 호출 → FastAPI API → 기존 서비스 → `patron_test` DB 경로로 검증했다. ASGI 클라이언트에서 실제 로그인·세션 쿠키·Origin 검사도 거쳤다. 임시 사용자와 QA 모델 두 개를 만들고 트랜잭션을 롤백했다. Provider 카탈로그는 가짜 데이터이며 OpenRouter 유료 추론은 호출하지 않았다.

다음은 수정 후 마지막 실행에서 측정한 요청 전체 시간이다. 모델이 적재된 상태의 작은 입력이며, 반복 측정한 지연 통계는 아니다.

| 요청 | 확인한 결과 | 시간 |
| --- | --- | ---: |
| 등록 QA 모델·업체 조회 | 모델 조회 도구와 출처 반환 | 3.32초 |
| 빈 시뮬레이션 이력 조회 | 이력 도구와 출처 반환 | 1.16초 |

총 10개 기본 시나리오가 통과했다. 상세 조회 사례는 대기 상태이고 모델별 결과가 비어 있으므로, 완료된 장문 응답의 요약 정확도를 검증한 것으로 해석하지 않는다. 날짜·상태의 자연어 표시 품질도 별도 평가 대상이다.

로그아웃은 204, 이후 에이전트 접근은 401을 확인했다. 조회·설정 준비로 새 AIRequest나 SimulationRun이 생성되지 않았다. 추가 실행에서 트랜잭션 종료 후 임시 사용자와 모델이 남지 않은 것도 확인했다. 최초 간단한 인사 요청은 모델 적재 약 6.99초를 포함해 약 11.2초였으므로, 처음 실행하거나 자동 언로드 후에는 더 오래 걸릴 수 있다.

## 실제 호출에서 반영한 수정

- 작은 모델이 중첩 객체를 문자열로 보내는 경우를 줄이도록 도구용 JSON Schema를 펼치고, 공통 설정은 직접 인자로 받는다. HTTP API 계약과 서버 검증은 그대로 사용한다.
- 요청하지 않은 현재 값은 패치에서 제외하고, 명시적 `null` 해제는 유지한다.
- 범위 밖의 설정을 모델이 임의로 유효한 값으로 바꿔 적용하지 못하도록 해당 요청을 중단한다. 실패를 완료로 안내하는 응답도 차단한다.
- 이력 조회는 한 번에 5개로 제한하며 모델에는 페이지 크기를 입력하도록 요구하지 않는다.

이 결과는 4B 모델로 초기 도구 사용을 시험할 수 있다는 근거다. 다양한 한국어 표현, 긴 대화, 실제 Provider 조합에서의 정확도와 P04 브라우저 적용 경험까지 보장하는 평가는 아니다. 설치 확인 후에도 기능은 기본 비활성화이며, 실행 방법은 [설정 안내](ASSISTANT.md)를 따른다.

## 답변 가독성 추가 확인

같은 날 답변의 표시를 개선한 뒤 로컬 브라우저와 실제 Qwen으로 날짜 답변·여러 항목 답변을 확인했다. 시간대가 있는 ISO 날짜는 화면에서 한국시간으로 바꾸고 소수 초를 생략한다. 모델이 날짜를 인라인 코드로 감싸도 일반 질문에서는 읽기 쉬운 날짜로 표시한다. 원문·ISO·JSON 등 원시 값 요청과 코드 블록은 원문을 유지한다.

강조·문단·목록·코드 구문을 구분하고 건수·토큰 수·USD 금액을 표시용으로 정리했다. 전송하는 대화 원문과 실제 설정은 표시 변환의 영향을 받지 않는다. 답변 작성 지침에는 결론 우선, 불필요한 ID·내부 필드명 생략, 상태의 한국어 표현을 추가했다. 이는 자유 형식 생성에 대한 지침이며 모든 표현이나 사실 판단의 정확도를 보장하는 것은 아니다.

수정 후 프론트엔드 718개 테스트와 타입·린트·빌드 검사, 에이전트 관련 백엔드 34개 테스트가 통과했다. 이 추가 확인에서는 OpenRouter 유료 추론이나 새 비교 실행을 요청하지 않았다.

## P05 상세 출처 연결 추가 확인

실행 이력·상세 조회가 실제 확인한 실행 ID와 요청 시각을 출처에 포함하도록 변경했다. 답변에 나온 ID나 요청 시각이 조회 결과와 일치하면 해당 출처를 우선하고, 특정할 수 없는 여러 결과는 실행별 출처로 제공한다. 모델이 임의로 적은 ID를 링크로 만들지 않는다.

실제 로컬 브라우저에서 최근 시뮬레이션을 질문한 뒤 출처 링크를 눌렀다. P05로 이동하고 기존 ‘시뮬레이션 실행 상세’ 창이 자동으로 열리며, 답변과 같은 실행 ID·당시 입력·설정·모델별 결과가 표시되는 것을 확인했다. 닫은 뒤에도 선택 실행과 조회 조건이 유지되었다. 이 확인에서는 새 비교 실행을 요청하지 않았다.

수정 후 프론트엔드 전체 724개, 에이전트·기존 이력·상세 관련 백엔드 130개 테스트가 통과했다. 타입·린트·포맷·프론트엔드 빌드도 통과했다. 사용자가 조정한 채팅창 높이 `h-160`은 유지했다.

9개 기본 시나리오를 확인했다. 새 AIRequest·SimulationRun은 각각 0개, 로그아웃 204·이후 접근 401, 롤백 후 임시 사용자 0개였다. OpenRouter 유료 추론은 호출하지 않았다. 시간은 한 차례 실행의 전체 요청 시간이며 지연 통계가 아니다.

초기 실제 검증에서 모델이 도구를 생략하거나 화면 기간을 임의로 바꾸고 미확인 건수를 금액처럼 설명하는 사례가 있었다. 사용량 전용 지침을 분리하고, 대상·기간·예산 상태는 사용자 요청과 적용된 화면 조건을 서버가 확인하도록 보완했다. 도구를 생략하면 전체 왕복 한도 안에서 한 번 재안내하며, 조회 근거가 없는 사용량·비용 답변은 차단한다. 미확인 건수는 금액 미상·합계 제외 안내와 함께 전달한다. 자유 형식 문장의 표현과 요약 누락까지 보장하는 평가는 아니다.

실제 브라우저에서는 고객 A·10월을 적용한 뒤 확정 비용 2.23 USD와 미확인 25건이 화면 카드와 일치함을 확인했다. 같은 대화를 유지한 채 P02로 이동하면 조회 기준이 바뀌었다. 내부 예산 초과 출처를 누르면 10월·예산 초과 조건의 전체 목록이 열렸고, ‘예산 상태 조건 해제’로 조건을 지울 수 있었다. 검증 세션은 로그아웃했다.

최종 프론트엔드 전체 737개 테스트와 타입 검사 통과. 린트·빌드도 통과했으며 안내 문구·출처 페이지 크기 변경 후 관련 21개 테스트를 추가 확인했다. 백엔드 Ruff 린트·포맷과 DB를 사용하지 않는 범위·대화·입력 검증 29개가 통과했다. 기간·집계·API 관련 묶음은 42개가 통과했다.

전체 백엔드 재검사는 2,686개 통과, 기존 모델 등록 테스트의 setup 오류 1개, Windows 심볼릭 링크 권한 테스트 1개 제외였다. 다른 작업 폴더 `logbase-patron-mock`의 pytest도 실행 중이었고, 공유 `patron_test` 초기화가 겹치며 `users`/`projects` 테이블 부재 오류가 간헐적으로 발생했다. 앞선 실패 모듈 67개는 분리 실행에서 모두 통과했다. 다른 작업의 테스트를 중단하거나 DB 설정을 바꾸지 않았으며, 전체 검사가 모두 통과했다고 기록하지 않는다. 공유 DB를 쓰는 pytest는 작업 폴더 간 순차 실행이 필요하다.
