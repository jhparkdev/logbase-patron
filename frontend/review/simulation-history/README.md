# P-05 시뮬레이션 결과 이력 예시

현재 브랜치는 `feature/fe-simulator`의 P-04 완료 커밋 `17bfd7e`에서 시작한 `feature/fe-simulation-history`다. P-04를 dev에 병합한 뒤 P-05를 병합하는 순서로 검토한다.

저장소 루트에서 개발 서버를 실행한다.

```powershell
corepack pnpm@12.15.0 --dir frontend dev
```

- 실제 P-05: `/simulation-history`
- 기존 데이터가 채워진 P-05: `/simulation-history-preview.html`
- 기본 주소는 `http://localhost:5173`이며 서버가 안내하는 포트가 다르면 해당 포트를 사용한다.

## 확인 가능한 동작

- 기간·시나리오·모델·실행 상태·Simulation ID 조건을 입력하고 조회한다. 기간은 KST, 기본 최근 30일, 최대 366일이다.
- 6개 데이터 열의 정렬 조건과 필터·페이지·선택 ID·상세 열림 상태를 URL에 보존한다. Prompt·입력 원문은 URL에 넣지 않는다.
- dev에 병합된 공통 `Pagination`과 `PAGE_SIZE`(10건)를 재사용한다. 기존 12건을 10건·2건으로 나누고, 검색·정렬을 바꾸면 첫 페이지로 돌아간다. 잘못된 페이지 번호는 1로, 결과 범위를 넘는 preview 주소는 마지막 페이지로 보정한다.
- 이력 안의 정렬·상세 변경은 스크롤 위치를 유지한다. 다시 준비 화면에서는 시뮬레이터 메뉴를 선택하고, 이력으로 돌아가면 원래 페이지와 상세를 복원한다.
- 실행 ID 또는 상세 보기로 당시 입력·설정·현재 모델 상태·모델별 결과를 확인한다. 우상단 ×, 하단 닫기와 Escape를 지원한다. 우상단 버튼은 상세를 스크롤해도 유지된다.
- 다시 준비하면 같은 예시 진입점 안에서 실제 P-04 컴포넌트에 조건을 복원한다. 새 실행 결과를 생성하지 않는다.
- 비활성·누락 모델 자리를 비워 교체·제외를 안내하며, 2개 미만이면 추가 모델 선택을 안내한다. 삭제된 시나리오는 원문을 유지하며 Custom으로 전환한다.
- 이미지 원본에 접근할 수 없거나 입력이 없으면 재실행을 제한한다. 과거 결과는 계속 확인할 수 있다.

## 데이터 출처와 한계

- 기존 `src/features/simulator/components/dbMock.fixture.ts`의 12개 실행·32개 최종 모델 결과를 재사용한다. 새 DB 데이터는 만들지 않았다.
- 당시 Prompt·입력·Schema·설정·원본 실행 ID·첨부 참조는 추적 중인 `backend/seed/patron_mock_data_v0.6.sql`의 동일한 12개 MOCK 행에서 추출했다. `history-inputs.fixture.ts`에 스냅샷을 저장했다.
- 현재 모델 표시는 2026-10-29에 추출했던 기존 mock 카탈로그 기준이다. 실제 최신 서버 상태 조회가 아니다.
- seed는 첨부 이미지 메타데이터만 제공하므로 이미지 원본은 접근 불가로 표시한다. 가짜 이미지 파일을 만들어 복원하지 않는다.
- 예시의 검색·정렬·페이지 분할은 개발용 폴더 안에서만 스냅샷에 적용한다. 서비스 컴포넌트는 전달받은 행과 순서를 유지하며, 실제 API가 전체 검색·정렬·페이지 처리를 담당해야 한다.
- 별도 개발 HTML 진입점이며 기본 배포 빌드에 포함되지 않는다. DB·Docker·OpenRouter 호출 없이 볼 수 있다.

## 후속 연결 지점

- 서비스 라우트의 조회·상세 데이터와 재시도 콜백에 TanStack Query/API adapter를 연결한다. 현재는 `unavailable` 상태이며 가짜 결과를 표시하지 않는다.
- `HistoryPage`는 조회 완료 상태의 `items`와 `total`, URL의 `page`로 공통 페이지네이션을 표시한다. 실제 API adapter를 연결할 때 `page`와 공통 `PAGE_SIZE`를 요청에 반영하고, 범위를 벗어난 페이지는 서버 응답에 맞춰 처리해야 한다. API 미연결·오류·빈 결과 상태에는 페이지 이동을 표시하지 않는다.
- `renderResults`는 라우트에서 P-04의 결과 표시 컴포넌트를 조합하는 자리다. P-05 기능에서 P-04 내부를 직접 import하지 않는다.
- 서비스 재실행 경로는 `/simulator?sourceRun=<원본 ID>`다. P-04에서 원본 조회·이미지 복원·현재 모델 검증을 완료한 후 `SimulatorRestore`에 값을 전달해야 한다. 현재 서비스 경로는 API 준비 안내를 표시한다.
- 실제 재실행에서는 기존 ID를 재사용하지 않고 서버가 새 ID와 기록을 생성해야 한다. UI 단계에서는 생성·저장 성공을 표시하지 않는다.
- P-04의 dialog를 공통 `shared/components/ui/Dialog.tsx`로 옮겼으며 기존 `SimulatorDialog` import는 유지했다. 상세 제목을 본문 스크롤 영역과 분리해 ID가 가려지지 않도록 했다. 페이지네이션 공통 코드는 dev의 구현을 그대로 사용한다.

## 검증 기록 (2026-10-30)

- 프론트엔드 타입 검사, 린트, 전체 196개 테스트, 배포 빌드를 통과했다.
- 브라우저 1280px에서 검색·상세 열기·닫기·포커스 복원, 전체 응답 창만 Escape로 닫기, P-04 원문·파라미터 복원, 비활성 모델 교체 안내와 이미지 접근 불가 시 재실행 제한을 확인했다.
- 숫자로만 된 시나리오 ID가 URL 왕복 중 숫자로 변환되어 검색에서 빠지는 예시 페이지 문제를 고쳤다. 라우터 기본 직렬화로 문자열을 유지하고 복합 필터 회귀 테스트를 추가했다.
- 배포 산출물에 예시 HTML과 mock 스냅샷이 포함되지 않는 것을 확인했다. 실제 서버 조회·저장·재실행 통합 검증은 수행하지 않았다.

커밋과 푸시는 사용자가 직접 진행한다.
