# P-04 데이터가 채워진 상태의 예시 페이지

저장소 루트에서 기존 개발 서버를 실행한다.

```powershell
pnpm --dir frontend dev
```

터미널에 표시된 서버 주소 뒤에 `/simulator-preview.html`을 붙인다. 기본 주소는 `http://localhost:5173/simulator-preview.html`이다. 서버가 이미 실행 중이면 주소만 열면 된다.

- 이력 탐색용 `/simulator-review.html`과 상태 필터·기록 선택·이전/다음 기능은 폐기했다.
- 실제 `SimulatorPage`를 재사용해 P-04의 입력·모델 선택·결과가 함께 채워진 모습을 보여준다. 서비스 코드에 mock 데이터 분기를 넣지 않는다.
- 기존 DB mock 스냅샷 중 `2026-10-22 10:00:00 KST`의 데이터 요약 시나리오 실행 한 건을 사용한다. 실행 ID는 `01a1611f-3e80-73c5-a130-3efa5a1f75de`다.
- 입력은 추적 중인 `backend/seed/patron_mock_data_v0.6.sql`의 동일 실행과 시나리오 정의를 대조했다. 린넨 셔츠 원피스 정보, Temperature 0.3, 최대 출력 512토큰을 복원했다.
- 모델은 Kimi K3.1 Pro, Mistral Nemo, Gemma 3 4B다. 결과는 성공 3건·확정 비용이며 기존 응답·토큰·시간을 그대로 표시한다. 이 실행은 이미지·JSON Schema를 사용하지 않아 해당 선택값은 비어 있고 검증은 미적용이다.
- 입력과 공통 설정을 편집하고 전체 응답을 열어볼 수 있다. 편집해도 저장된 예시 결과는 바뀌지 않는다. 실제 실행·조회·저장은 하지 않고 비교 실행 버튼은 비활성화된다.
- 모델 검색 모달에서 전체 모델·즐겨찾기 목록을 전환하고 별 버튼으로 즐겨찾기를 등록·해제할 수 있다. 검색은 두 목록에 적용되고 비교 대상 선택과 즐겨찾기는 독립적으로 바뀐다.
- 제작사 배지는 카탈로그, 모달의 선택 목록과 본문 비교 모델에 같은 색·이름으로 표시한다. 예시의 제작사는 seed의 `models.provider` 값을 사용하며 실행 Provider와 구별한다. 새 카탈로그 adapter는 `ModelChoice.creator`에 제작사를 전달해야 하고, 값이 없으면 ‘제작사 미확인’으로 표시한다. 제작사명으로도 검색할 수 있다.
- 미리보기의 즐겨찾기는 해당 페이지의 메모리에서만 유지하고 새로고침하면 초기화한다. 계정별 DB 저장이나 실제 즐겨찾기 API는 아직 연결하지 않았다. 서비스 화면은 상태·이벤트 props를 전달받을 때만 즐겨찾기를 사용할 수 있으며, 미연결 상태를 가짜 성공으로 표시하지 않는다.
- 별도 개발용 HTML 진입점이며 서비스의 배포 빌드에는 포함되지 않는다. DB나 Docker를 켜지 않아도 볼 수 있다.

## 모델별 튜닝 검토

- 본문의 ‘모델별 설정’을 펼쳐 ‘모델별 설정 사용’을 켜면 해당 비교 항목만 편집한다. 빈 값은 공통 설정 → 시나리오 기본값 순으로 이어받고, 모두 비어 있으면 요청에서 생략한다.
- ‘다른 설정으로 비교’는 같은 모델·Provider를 독립된 비교 항목으로 복제한다. 복제를 포함해 최대 4개다. 개별값과 항목 ID는 카탈로그 재적용·다른 항목 제거 후에도 유지한다.
- 검색 모달은 한 모델부터 적용할 수 있다. 실제 비교 실행은 설정이 다른 복제 항목을 포함해 2~4개가 필요하다.
- 공통 설정에는 Temperature·최대 출력 토큰·추론 강도(effort)를 지정한다. 공통 effort 선택지는 활성 카탈로그에서 확인된 목록을 모아 표시하므로, 선택한 모델 모두가 그 값을 지원한다는 뜻은 아니다. 모델별 지정값이 있으면 우선 적용하며, 각 항목에 실제 적용될 설정을 지원하지 않거나 effort의 지원 선택지를 확인할 수 없으면 실행 전 차단하고 사유를 표시한다. 설정을 조용히 생략하거나 바꾸지 않는다.
- 공통 effort는 접기·재실행 입력 복원·화면 제출값에서 보존하며, ‘기본 설정으로’를 누르면 다른 공통값과 함께 지운다. 개별 설정은 유지한다. 실제 DB 저장과 AI 호출은 아직 연결하지 않았다.
- ‘공통 설정으로’는 개별값을 지운다. 체크만 해제하면 편집값은 남겨 두되 요청에는 포함하지 않는다.
- `tuning-preview.fixture.ts`는 **검토용 가상 지원 정보**다. Kimi 예시는 숫자형·선택형, DekaLLM의 Mistral 예시는 숫자형, 나머지는 지원 정보 미제공 상태를 보여 준다. 실제 모델의 지원 여부·범위·추론 강도 선택지가 아니다. 기존 DB 스냅샷은 수정하지 않는다.
- 서비스에서는 `ModelChoice.tuningParameters`로 확인된 설정 종류·범위·선택지를 전달해야 편집과 복제가 가능하다. 제작사나 모델 이름으로 지원 정보를 추측하지 않는다.
- 화면 제출값은 `SimulatorDraft.comparisons`이며 항목별 `comparisonId`, `modelKey`, `settings`를 담는다. 기존 HTTP 요청 형식이 아니므로 API 연결 단계에서 생성된 계약 타입으로 변환해야 한다. 현재 백엔드는 변경하지 않았다.
- 실행 콜백이 연결된 화면은 확인창에서 항목별 **요청 설정**을 표시하고, 같은 대상의 동일한 요청 설정을 차단한다. 서버의 기본값 적용 후 최종 설정·해시 중복 검증은 백엔드 연결 단계에 남아 있다.

### 수동 확인

1. 첫 모델의 개별 Temperature를 0.7로 바꾸고 접었다 펼친다. 공통 Temperature 0.3과 다른 항목은 유지된다.
2. 개별 설정 체크를 해제했다 켠 뒤 편집값이 남는지, ‘공통 설정으로’를 누르면 지워지는지 확인한다.
3. 첫 모델을 복제해 추론 강도를 ‘높음’으로 바꾼다. 4개가 되면 추가 복제가 비활성화된다.
4. 앞 항목을 제거하고 검색 모달을 재적용한다. 남은 항목의 편집값은 유지되고, 모달의 개수에는 복제도 포함된다.
5. Mistral(DekaLLM)은 숫자형만, 지원 정보가 없는 모델은 안내 문구와 비활성 체크박스가 표시된다.
6. 편집해도 기존 결과는 바뀌지 않으며 실제 실행 버튼은 비활성화된다. 오류·중복 차단·실행 확인창은 실행 콜백을 사용하는 컴포넌트 테스트에서 검증한다.
7. 공통 설정에서 추론 강도를 ‘높음’으로 선택한 뒤 접었다 펼치면 값이 유지된다. ‘기본 설정으로’를 누르면 기본값 사용으로 돌아가며 모델별 지정값은 유지된다.
